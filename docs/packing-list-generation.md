# 「CheckMan」初期持ち物リスト生成機能 技術・構成メモ

## 1. 実装概要

旅行先、旅行日数、出発日から自動判定した季節、交通手段、旅行目的、アクティビティ、参加メンバーの情報から、旅行条件に合う初期持ち物リストを自動生成する機能を追加した。

今回の実装では、外部の生成AI APIやAPIキーを使用せず、自作JSONの持ち物マスタとルールベースの推薦処理を採用している。基本的な必需品を確実に生成でき、通信障害やAIサービスの停止に影響されない構成を優先した。

## 2. 採用技術

| 技術 | 用途 |
| --- | --- |
| React 19 | 旅行条件入力画面と生成結果確認画面のUI |
| TypeScript | 旅行情報、持ち物、生成条件の型定義と安全な変換 |
| TanStack Start | 既存アプリのルーティングと画面構成 |
| Vite | 開発サーバーとフロントエンドのビルド |
| JSON | 持ち物マスタおよび条件別ルールの管理 |
| LocalStorage | 生成した旅行情報・チェックリストの既存保存方式を継続利用 |
| 独自ルールエンジン | 旅行条件に応じた候補の抽出、統合、数量設定 |

### AI機能としての位置付け

現段階では機械学習モデルではなく、旅行条件を解釈して候補を推薦する「ルールベース推薦」をAI機能のPhase 1として採用した。

Transformers.jsによるEmbedding推薦も検討したが、次の理由から今回は導入していない。

- モデルファイルの初回ダウンロードが必要になる
- 初期ロード時間とブラウザー負荷が増える
- 依存パッケージが増え、既存機能へ影響する可能性がある
- 現在の目的は短期間で安定動作する初期リスト生成であり、ルールベースで十分に達成できる

将来Transformers.jsを追加する場合も、必需品はルールベースで保証し、モデル推薦は追加候補を補う用途に限定する想定である。

## 3. ディレクトリ構成

```text
src/
├─ data/
│  └─ packing-items.json              # 持ち物マスタと条件別ルール
├─ services/
│  └─ packing-list-generator.ts       # 生成処理の中心
├─ utils/
│  ├─ item-matcher.ts                 # JSON検証・条件照合
│  └─ duplicate-remover.ts            # 重複除去
├─ lib/
│  ├─ trip-types.ts                   # Season、TripPurpose等の型定義
│  └─ trip-templates.ts               # 新生成処理と既存処理の接続・フォールバック
└─ routes/
   └─ setup.tsx                       # 条件入力・生成結果確認UI
```

大規模なディレクトリ変更や既存状態管理の置き換えは行わず、生成処理に必要な責務だけを分離している。

## 4. データ構成

`src/data/packing-items.json`では、持ち物を次の条件ごとに分類している。

- `common`: すべての旅行に共通する必需品
- `travelType`: 国内・海外旅行
- `season`: 春・夏・秋・冬
- `transportation`: 飛行機、電車、車、バス、船など
- `purpose`: 観光、帰省、出張、アウトドアなど
- `activities`: 海・プール、温泉、ハイキングなど
- `destinations`: 沖縄など旅行先のキーワードに対応する項目
- `ageGroups`: 小学生、幼児、乳児など年齢区分別の項目
- `lodging`: ホテル、キャンプ、民泊など
- `duration`: 一定泊数以上で必要になる項目

各持ち物には、主に次の情報を持たせている。

```json
{
  "key": "sunscreen",
  "name": "日焼け止め",
  "emoji": "🧴",
  "priority": "mid",
  "bag": "checked",
  "reason": "強い日差しから肌を守ります。"
}
```

`key`は複数の条件から同じ持ち物が選ばれた場合の重複判定に利用する。

## 5. 生成処理の流れ

```text
旅行条件入力（setup.tsx）
        ↓
PackingListGenerationParamsへ変換
        ↓
packing-list-generator.ts
        ├─ commonを取得
        ├─ 国内／海外を照合
        ├─ 季節・交通手段・目的を照合
        ├─ 旅行先キーワードを照合
        ├─ アクティビティ・宿泊先を照合
        ├─ 泊数・メンバー年齢を照合
        ↓
item-matcher.tsでJSONデータを検証
        ↓
duplicate-remover.tsで重複を除去
        ↓
既存のPackItem形式へ変換
        ↓
生成結果確認画面
        ↓
既存チェックリスト・LocalStorageへ保存
```

### 数量の自動設定

既存の数量機能に合わせ、旅行日数から衣類の初期数量を設定する。

- 着替え（上）：旅行日数分
- 下着・靴下：旅行日数分
- 着替え（下）：旅行日数のおよそ半分

### 担当者の設定

- 通常の持ち物は「自分」を初期担当者にする
- 子ども向け項目は、登録された最初の子どもを担当者にする
- 該当メンバーが存在しない場合もエラーにせず、安全な既定値を使用する

## 6. UIとの接続

`src/routes/setup.tsx`の旅行内容入力では、次の情報を生成処理へ渡す。

- 季節：選択欄は設けず、出発月から自動判定
- 旅行目的：観光、帰省、出張、アウトドアなど

最終確認画面では、入力した条件、生成件数、生成された候補を表示する。

確定後は既存の`Trip`および`PackItem`データ形式へ保存するため、検索、並び替え、一括編集、買い物リスト、担当者設定などの既存機能をそのまま利用できる。

## 7. 安定性とエラー対策

- JSON内の不正な項目は無視し、有効な項目だけで処理を継続する
- 項目の`key`または正規化した名前で重複を除去する
- JSONルールから生成できない場合は、既存のハードコードされた初期リスト生成へフォールバックする
- 外部通信を行わないため、API障害やAPIキー切れの影響を受けない
- `Trip`へ追加した季節・目的は任意項目とし、既存LocalStorageデータとの互換性を維持する

## 8. 実装結果

「沖縄・3泊4日・夏・飛行機・観光・海水浴」の条件では、水着、日焼け止め、ビーチサンダル、モバイルバッテリー、健康保険証・身分証などを含む初期リストを生成できる。

同一項目は複数のルールに一致しても1件に統合され、生成結果は既存チェックリストへそのまま反映される。
